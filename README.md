# subtitledb-stremio

The Stremio addon for [TheSubtitleDB](https://thesubtitledb.org). One Cloudflare Worker
at `api.thesubtitledb.org/integrations/stremio/`, published to the Stremio community
catalog.

Website: <https://thesubtitledb.org>

Install page: <https://api.thesubtitledb.org/integrations/stremio/configure>

Or paste `https://api.thesubtitledb.org/integrations/stremio/manifest.json` into Stremio's **Add addon**
box.

## What it does

Stremio hands an addon an IMDb id, and for a series the season and episode with it.
That is exactly what `/v1/by-imdb/:imdb/season/:s/episode/:e` answers, so the lookup is
one request per play with no search and no ladder.

The subtitle URLs point back at this Worker rather than at the API. Stremio renders
SubRip and WebVTT; the corpus is mostly SubRip with a long tail of SubStation Alpha,
and `/get` serves the stored bytes untouched. So `/s/:id.vtt` fetches the row and
converts it, with the same converter the browser players use. That also puts every
subtitle behind this Worker's cache instead of the API's rate limiter.

## Where it lives

It is mounted on a path on the read API's own hostname, not on a subdomain of its own.
That is a Worker **route**, `api.thesubtitledb.org/integrations/stremio/*`, never a
custom domain: the hostname is a proxied CNAME to the cloudflared tunnel in front of
the API, and a custom domain takes the whole hostname, which would take the corpus API
down with it. A route runs in front of the origin for the matched prefix only, so
`/v1` and `/get` never reach this Worker.

`ADDON_BASE` in `wrangler.toml` holds the origin **and** the path, and every URL the
addon hands Stremio is built from it. It is the one place the mount point is written
down; the routes below are all relative to it.

## Routes

| Route | What it serves |
|---|---|
| `/manifest.json`, `/:config/manifest.json` | the addon manifest |
| `/configure`, `/:config/configure` | the settings page, which builds an install URL |
| `/subtitles/:type/:id.json` | the lookup, with or without a `/:extra` segment and a `/:config` prefix |
| `/s/:id.vtt` | one subtitle, converted to WebVTT, immutable |
| `/health` | a deploy probe |
| `/logo.png` | the manifest logo, generated by `tools/make-logo.py` |

Every route answers with `access-control-allow-origin: *`, which the protocol requires
on the manifest as well: web.stremio.com is a browser page fetching a third-party
origin, and an addon that forgets CORS on one route fails there and nowhere else.

## Settings

A configured install is a different manifest URL: the settings ride in a base64url
path segment in front of every route, because Stremio has no per-addon storage. The
configure page encodes them in the browser.

| Setting | Default | Notes |
|---|---|---|
| languages | `en` | Ranked, up to 16. Empty means every language, in the corpus's own order. |
| hearing impaired | include | `include`, `prefer` or `exclude`. |
| limit | 50 | Rows asked of the API per title, split across the languages. Caps at 100. |

Anything unparseable in the segment falls back to the defaults rather than erroring: an
install whose URL was mangled has to keep working.

Languages are a picker, not a box you type a list into. The chosen ones are a ranked
list you reorder, because the order is the preference and a comma separated string is
the worst control there is for one: nothing to discover, nothing to reorder without
retyping, and no way to know a spelling was understood. The free-text box it replaced
carried its own forty-entry spelling subset, so a name outside it resolved to nothing,
the term was dropped in silence, and "Tagalog" produced an install configured for every
language that looked exactly like an install configured for Tagalog.

The page ships `spellingTable()` and `nameTable()` from `src/languages.ts`, the same
tables `toCode` uses, so search matches an alias as well as a name. Sixty-eight of the
corpus's 185 codes have a name to browse for; searching one of the other 117 offers it
as a bare code where it was typed, rather than in a second box somewhere else. Every
setting is drawn server-side as well, so the page is right in a webview before its
script runs, and it makes no network calls at all. `test/configure.test.ts` pins that,
including that the two sides agree on every spelling.

## Two API traps this addon is built around

`lang` and `format` are **ignored on a series or season bundle**: the tree is served
unfiltered by design. So the addon filters locally exactly where the API's filter did
not run, and `test/api.live.test.ts` pins both halves.

`lang` takes up to 16 comma separated codes but applies **one shared `limit` across all
of them**, filled in the API's order rather than ours. `?lang=fr,en&limit=100` on
tt0111161 comes back as 100 English rows and 0 French, so `order()` has nothing French
left to put first and the second language a viewer picked comes back empty. Raising the
limit is the wrong axis. `lookupAll()` therefore sends one request per language with
its own share of the limit, and the first goes alone because its answer is what says
whether `lang` applied at all. That is up to `n` upstream requests per lookup against a
300/min anonymous ceiling, which is what the setting costs to mean what it says;
`test/fanout.test.ts` pins the request count as well as the result.

## Shared code

The converter and the release-name similarity function are vendored verbatim from
`thesubtitledb/subtitledb-cdn` into `src/upstream/`, because `@subtitledb/core` is a
private workspace package that cannot be installed here. `plugins/shared/match-cases.json`
is copied into `test/fixtures/` and read by `test/shared-cases.test.ts`, which is the
fifth reader of that file: the four upstream suites are TypeScript, Python, C# and Lua.

`tools/check-upstream.mjs` fails CI when a copy stops matching upstream. It needs a
token that can read the private repo: `UPSTREAM_TOKEN`.

## Working on it

```
npm ci
npm run lint
npm run typecheck
npm test
npm run test:live
npm run check:upstream
```

`npm run dev` runs it locally on wrangler. `npm run deploy` needs
`CLOUDFLARE_API_TOKEN`; CI does it on a push to main and then probes what it deployed.

The API key is optional and is a secret, not a var:

```
npx wrangler secret put SDB_API_KEY
```

Without it the addon is on the anonymous rate-limit tier, which is 300 reads a minute
for the whole addon rather than per viewer. With it, 1800. **It is not set in
production**: minting a key needs an account on thesubtitledb.org, and until one exists
the Worker's own cache is what keeps the addon under the anonymous ceiling. Lookups are
cached for 30 minutes and converted bytes for a year, so a popular title costs one
upstream request per half hour no matter how many people are watching it.
